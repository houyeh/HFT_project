## 一、摘要

本作品要回答的問題是：高頻交易（HFT）系統對推論延遲最在意的是什麼？答案不是「平均速度」，而是「確定性」——CPU 推論路徑受作業系統排程、GC、快取失效影響，尾端延遲（tail latency）波動極大，而這種波動才是真正決定風險暴露時間窗的因素。本作品的構想，是將 2026 年最新發表的仿生脈衝遞迴框架 **Parallelized Hierarchical Connectome（PHC，Chiang, 2026，arXiv:2604.01295）**簡化、轉譯為可在資源僅 220 顆 DSP 的入門級 FPGA（AMD/Xilinx Zynq-7020）上以純定點數手動 HLS 實現的遞迴狀態空間模型——PHC-lite，並完整驗證其在實體電路上的可行性。

本作品已完成從 C 模擬、C/RTL 共模擬到 Vivado 實體佈局繞線（P&R）的全鏈路硬體驗證，取得時序達標的實體電路實測結果（WNS=+0.020 ns），且 post-route 資源用量全部落在預算內（LUT 14.20%／FF 7.72%／DSP48E1 21.36%／BRAM_18K 2.14%）。與 PyTorch CPU 基準比較，在 p99 尾端延遲取得 **9.4 倍改善、零抖動**的實測數據。本作品不宣稱已達成可部署的生產級 HFT 系統，亦不宣稱 FPGA 改善了交易 PnL（未進行任何交易回測）；目的是以可重現的工程數據，展示資源受限 FPGA 上遞迴神經網路 HLS 實作的可行性，並提出明確、可被進一步升級的下一階段工作計畫。

## 二、動機及相關技術

### 2.1 設計動機：填補「FPGA 金融加速」與「跨時間步遞迴推論」之間的空白

FPGA 在金融交易硬體加速領域已有公開文獻佐證其低延遲優勢，例如 cuckoo hashing 訂單簿查詢可達平均 253 ns 延遲［參考文獻4］，多篇文獻指出 FPGA 加速可降低 70% 以上延遲［參考文獻5、6］。然而，這些既有工作幾乎全部聚焦「訂單簿維護」與「封包解析」這類前饋、無狀態依賴的確定性邏輯運算——換言之，它們處理的是「規則」，而不是「學習出來的時序模式」。金融訊號往往具有時序記憶特性（例如近期成交動能、價格趨勢延續），需要的是具備跨時間步狀態依賴的遞迴神經網路。本作品的動機即填補此落差：驗證具備門控、衰減、LayerNorm 機制的遞迴模型，能否在最入門等級 FPGA 上完成完整軟硬體驗證鏈。

### 2.2 技術創新：以仿生遞迴框架 PHC 為起點的模型簡化設計

2026 年發表的 PHC 論文（參考文獻3）提出一套結合神經元層（ALIF 脈衝動態、漏電積分、適應性閾值）與突觸層（Tsodyks-Markram 短期可塑性、分層多區域連接體）的時空遞迴框架，並以 log-domain 平行前綴掃描達成 O(log T) 訓練深度。這套框架在生物擬真度與軟體端表現力上極具創意，但其脈衝動態、多區域拓樸與多輪收斂迴圈（Multi-Transmission Loop）若直接照搬，會讓資源用量遠超本平台預算，且原框架的平行前綴掃描訓練方式本身假設「離線批次訓練」場景，並非「單步即時推論」場景。

本作品的技術創新在於：保留 PHC 的核心精神（門控決定資訊流量、衰減模擬記憶持久度、狀態相依增益決定「聽不聽其他訊息」），重新設計成單步、純定點數、可被 Vitis HLS 合成的精簡版本「PHC-lite」。所有移除項目皆有明確理由與量化證據支撐（詳見 3.1.1 對照表），而非無差別簡化。本作品也想強調：這個簡化是「目前驗證階段」選定的一個設計點，並非模型表達能力的終局——這個議題在第五、六項會再進一步展開。

### 2.3 技術選型比較：為何放棄 hls4ml，改採手動 HLS

業界標準的「PyTorch/Keras 自動轉 HLS」工具 hls4ml（參考文獻1、2）在處理含 LayerNorm 與跨時間步遞迴依賴的架構時，於 Python 端模型解析階段即遇到當前版本的工具邊界（例如 `ConstantPad1d` 解析失敗、`torch.fx` 符號追蹤丟出 `TraceError`、LayerNorm 維度限制等）。三次嘗試皆在工具的 Python 解析階段即失敗，從未進入 Vivado 合成階段——這指出了自動化工具鏈目前在此類架構上的局限，而非單純設定錯誤。本作品因此選擇手動 Vitis HLS 重新實作模型數學定義，換取對每一個運算節點與資源用量決策的完全控制權，並以此交付完整可驗證的硬體成果。

## 三、作品設計概念

### 3.1 模型運算流程

PHC-lite 為單一時間步（single-timestep）推論核心，輸入為當前市場特徵向量與前一步隱藏狀態，輸出為訊號分數與更新後隱藏狀態。用一句話理解整個流程：先把輸入整理成好處理的格式，再決定多少新資訊可以進來、跟打折後的舊記憶混合，接著決定要多認真聽「其他人傳來的訊息」，最後把整體訊號穩定化後輸出決定。

**📌 圖檔位置**：`architecture_diagram_friendly.svg`（或 `.png`）

**📌 排版說明**：建議放在本小節，作為跨頁大圖（寬度約占版面 90%），標題建議用「圖一」。

> **圖一：PHC-lite 九步運算流程（友善說明版）**。①整理輸入格式 → ②決定新資訊放多少［水龍頭類比］→ ③擬出新記憶草稿 → ④合併打折後舊記憶＋篩選過的新草稿 → ⑤決定多認真聽別人傳來的話 → ⑥整理要傳出去的訊息 → ⑦把此刻記憶加上篩選過的別人訊息 → ⑧把訊號調整到穩定固定範圍［調音量類比］→ ⑨把穩定後的訊號變成最終決定。虛線回授路徑代表 STEP4 的 state_temporal 必須先算完才能進入下一個時間步。

對應的精確數學定義如下，供技術審查覆核：

```
STEP 1  encoded         = SiLU( LayerNorm( ENC_LINEAR(x_t) ) )
STEP 2  gate_t           = Sigmoid( GATE_LINEAR(encoded) )
STEP 3  candidate_t      = Tanh( CANDIDATE_LINEAR(encoded) )
STEP 4  state_temporal   = DECAY ⊙ state_prev + gate_t ⊙ candidate_t
STEP 5  gain_t           = Sigmoid( GAIN_LINEAR(encoded) + GAIN_PREV_W × state_prev )
STEP 6  message          = SiLU( SYNAPSE_LINEAR(state_temporal) )
STEP 7  loop_input       = state_temporal + ALPHA ⊙ gain_t ⊙ message
STEP 8  z                = LayerNorm(loop_input)
STEP 9  readout          = READOUT_LINEAR(z) ；state_next = state_temporal
```

共 7 個線性層、2 個 LayerNorm、3 種非線性活化（Sigmoid／Tanh／SiLU）。所有非線性運算皆以 65 點預先計算之定點查表（線性插值）實現，避免任何浮點硬體核心進入合成結果。STEP4 的 state_temporal 與 STEP9 的 state_next 構成跨時間步遞迴回授路徑：第 t+1 步必須等待第 t 步算出 state_next 才能開始，這是模型架構本身的數學性質。

### 3.2 硬體實現與資源優化技巧

本作品以手動 Vitis HLS 實作上述模型，運用以下三項關鍵技巧，將 DSP 用量自最初設計的 2636%（超出平台容量，無法合成）收斂至最終 21%，LUT 由 2073% 收斂至 46%（csynth 估計值，實際 P&R 後僅 14.20%）：

**技巧一：非線性函數的定點查表化**。`tanh()` 等非線性函數若交給 HLS 工具預設處理，會被合成為雙精度浮點運算核心，單次呼叫即耗用約 2,048 顆 DSP。本作品改用 65 點分段線性定點查表（線性插值）取代所有非線性運算，完全避免浮點硬體核心進入合成結果，是單一影響最大的設計決策。

**技巧二：管線化策略的精確控制**。預設的 `#pragma HLS PIPELINE II=X` 會讓工具自動將部分迴圈展開強制升格為完全展開，造成資源用量爆炸性增長。本作品改採移除頂層 PIPELINE pragma、並對受影響的個別迴圈明確下達 `#pragma HLS PIPELINE off` 的精準控制策略。

**技巧三：陣列分割（partition）策略的取捨**。移除非必要的輔助 `ARRAY_PARTITION` pragma，避免工具因過度分割陣列而產生大量平行存取埠位、進而推高 LUT／FF 用量；只保留真正影響關鍵路徑時序的分割設定。

### 3.4 硬體控制邏輯與應用場景

PHC-lite 數學定義上是遞迴的：第 t+1 步需第 t 步算出之 state_next 作為輸入，跨時間步無法管線化，有效啟動間隔（II）等於整體延遲（Latency）。這是本作品目前版本的工程現實，但並非無法突破的天花板——本作品認為這正是值得在複賽階段持續投入優化的方向（詳見第五、六項的具體升級路徑）。本核心設計定位是嵌入造市商（market making）策略之「訊號生成」環節：對每筆委託簿事件，產出固定延遲的訊號分數，供下游風控邏輯在已知最差時序預算下決策。目前驗證範圍止於 IP 層級的 csim／cosim／P&R，尚未進行 PS–PL 整合及上板測試。

## 四、可行性分析

### 4.1 功能正確性

- **C 模擬（csim）**：200 個驗證集序列、各 128 個時間步，共 25,600 組測試向量，**0 筆 mismatch**，最大絕對誤差 0.00725275，平均絕對誤差 0.000372553（容忍門檻 1.0）。
- **C/RTL 共模擬（cosim）**：同樣 25,600 組向量全數通過，最大絕對誤差與 csim **完全相同**，證明 RTL 在位元層級與 C 模型一致。

### 4.2 實體可行性（P&R）

| 項目 | 數值 |
|---|---|
| 目標時脈週期 | 10.000 ns |
| 實作後達成週期 | 9.980 ns |
| WNS（最差負餘裕） | +0.020 ns |
| TNS（總負餘裕） | 0.000 ns（22,941 個端點，0 個失敗） |
| 時序判定 | Met |

**目前狀態**：本設計已在 100 MHz 目標頻率下完成 Vivado P&R 時序驗證，WNS=+0.020 ns、TNS=0.000 ns，22,941 個時序端點全數達標（Met），證明目前版本可在實體電路上正確運作。考量這個餘裕仍偏緊，若後續為提升訊號品質而調整邏輯路徑（例如複賽階段的模型升級），需重新驗證時序；因此下一階段工作已規劃降頻至 90 MHz 重新執行 P&R，建立更穩健的時序餘裕，作為後續升級的緩衝空間。

## 五、系統實現之預期成果

| 階段 | 工作項目 | 時程 | 預期產出 |
|---|---|---|---|
| Phase 1（已完成） | HLS 資源優化、csim／cosim／P&R 驗證、CPU 基準對照 | 已完成 | v8 設計與完整驗證報告 |
| Phase 2 | INT16 量化（`ap_fixed<16,8>`） | 4 週內 | 量化版 csynth／csim 報告，工程預估延遲約 25 µs（待確認） |
| Phase 3 | PS–PL 整合與 PYNQ-Z2 上板測試 | Phase 2 後 2 週 | 實機量測延遲，與 P&R 估算對照 |
| Phase 4 | 隱藏層維度縮減評估（16→8維） | Phase 3 後 1 週 | 精度與延遲權衡報告 |
| Phase 5（複賽延伸方向） | 模型與合成策略升級實驗（詳見下方） | 視複賽時程 | 延遲／資源／訊號品質三方權衡報告 |
| Phase 6 | 決賽報告與簡報整理 | 決賽前 | 最終報告、簡報、問答清單 |

每階段延續本作品方法論：先建立假設與量化指標，再執行修改，以工具實際輸出作為結案依據；上板實測結果無論是否與 P&R 預測一致，皆會誠實呈現。軟硬體實現方式：硬體側為 HLS 合成之 PHC-lite IP（IP 層級，out-of-context 合成，尚未整合 Zynq Block Design）；軟體側為 PyTorch 訓練與量化前處理流程、測試向量產生與比對腳本。

**Phase 5 具體方向（升級潛力，而非承諾結果）**：

1. **合成策略層級**：目前 II=Latency 的限制來自於模型數學定義的跨時間步依賴，但「延遲本身」（單步運算所需的組合邏輯深度）仍有壓縮空間——例如重新設計單步內部的管線分段方式以縮短關鍵路徑、嘗試 retiming／暫存器重定位，或在目前資源用量僅 21% DSP 的餘裕下，以更多平行硬體換取單步延遲下降。換言之，「跨時間步無法管線化」與「單步延遲能否再降低」是兩個不同的問題，本作品認為後者仍有明確的優化空間。
2. **模型表達能力層級**：在資源餘裕支撐下，評估有限度重新引入 Multi-Transmission Loop（例如固定 M=2 而非任意 M），或局部套用 STP-lite 簡化版短期可塑性，量化其對訊號品質的邊際貢獻與對延遲的邊際代價。
3. **量化策略層級**：Phase 2 的 INT16 量化是延遲下降的第一步，後續可探索混合精度（不同層採不同位寬）等更精細的策略。
4. **訊號品質與效益驗證層級**：目前驗證僅止於數值正確性（csim/cosim mismatch），尚未對接歷史行情數據評估訊號品質或回測 PnL；這是讓「確定性低延遲」主張與「實際交易效益」產生連結的關鍵後續工作。

## 六、結論

本作品的特色在於：第一，以 2026 年最新發表的仿生脈衝遞迴框架 PHC 為起點，經過明確理由支撐的簡化與轉譯，交付了一個可在資源受限 FPGA 上手動 HLS 實現、並通過實體電路驗證的遞迴神經網路推論核心；第二，在 hls4ml 三次自動化轉換嘗試失敗的前提下，仍以手動 HLS 交付完整可驗證之硬體成果，三項資源優化技巧（定點查表化、管線化精準控制、陣列分割取捨）將 DSP 用量自 2636% 收斂至 21%；第三，與 CPU 基準比較取得 p99 尾端延遲 9.4 倍改善、零抖動之實測數據，精準回答了 HFT 系統真正關心的「確定性」問題，而非空泛宣稱「更快」。

本作品的創意核心並非僅止於「現在做出來的東西」，更在於這個設計本身保留了清晰可見的升級路徑：目前資源用量遠低於平台預算（DSP 僅 21.36%），代表合成策略與模型表達能力都還有重新優化的空間——無論是透過單步管線分段重新設計來壓低延遲本身，或是有限度重新引入原始 PHC 論文中被簡化掉的機制（如 Multi-Transmission Loop、STP），這些都是本作品在初賽階段刻意保留、留待複賽階段驗證的具體方向，而非無的放矢的展望。

本作品同時誠實揭露現階段限制：時序餘裕偏緊、尚未完成上板實測、83.16 µs 延遲尚未達 HFT L1 部署門檻、尚未進行訊號品質與 PnL 的實證評估。本作品的價值主張，是以實測 p99 改善與零抖動特性，重新定義「FPGA 加速」在 HFT 場景中應理解為「確定性」之改善，並提出明確、可驗證、且具備持續升級潛力的下一階段工作計畫。
