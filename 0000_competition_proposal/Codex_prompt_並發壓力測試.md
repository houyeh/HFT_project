# 給 Codex Agent 的任務說明：CPU 並發壓力測試（deadline miss rate）

## 背景（你需要知道但不要自己腦補的事）

- 既有結論：FPGA固定延遲83.16µs；CPU單執行緒基準（LibTorch C++）平均74.54µs、中位數51.0µs、p99 636.7µs、最小43.8µs。這組CPU數字是在**單一推論序列、系統閒置**情境下測的，不代表真實多標的並發情境下的表現。
- 這次任務的目的：在CPU上模擬多標的/多串流**並發**推論負載，量測延遲分佈如何隨並發數惡化，藉此補強「FPGA確定性」這個論點——不是要證明FPGA平均更快（目前FPGA平均並不比CPU快），而是要證明CPU在並發負載下會出現delay miss，FPGA不會。
- **這次任務刻意不碰PnL/成交回測**。是否成交、成交後對PnL的實際影響，需要的是市場replay資料，這是之後要跟指導教授要的資料，現在沒有，不要用任何方式估算或假設PnL影響，這次只做延遲量測與deadline miss統計，描述上要保持「這是延遲面的觀察，經濟後果留待未來工作」。

## 你要做的事（依序）

1. **先盤點現有CPU benchmark程式**：找到原本產出74.54/51.0/636.7/43.8µs這組數字的LibTorch C++ benchmark原始碼（不要自己猜路徑，先搜尋專案內哪個檔案/目錄產生過這組數字），回報它目前的執行方式（單執行緒？單進程？有沒有thread pinning/affinity設定？）。**不要假設它能直接套用到並發情境，先讀完再回報**。

2. **設計並發版本**：在同一段程式邏輯基礎上，改成可指定並發數N的版本（N個獨立的推論串流同時跑，各自重複呼叫同一個inference function），而不是重寫整套benchmark。並發數要測：N=1（對照組，應該重現原本74.54µs那組數字，作為sanity check）、N=2、N=4、N=8（機器實際核心數，已確認為8 cores）。N=8是否要加測N=16（超訂閱，故意讓並發數超過實體核心數，模擬資源更緊張的情境）由你先跑完N=8評估後回報建議，不要自己決定要不要做就直接做。

3. **每個並發檔位**跑10,000次推論，重複兩輪獨立量測（同一檔位跑兩次完整的10,000次，不是把20,000次混在一起算），分別回報兩輪的p50/p95/p99/平均/最小值，讓我能看兩輪是否一致（這是檢查量測穩定性用的，不是要你取平均蓋掉差異）。

4. **新增 deadline miss rate 指標**：deadline門檻 = FPGA的固定延遲83.16µs。對每個並發檔位，計算CPU推論延遲超過83.16µs的比例（例如N=8時可能很高比例超過）。這是這次實驗真正要拿出來用的新數字，要跟原本的p50/p95/p99並列回報，不要省略。

5. **環境誤差控制**：跑測試時，回報當下機器的背景負載狀態（是否有其他程序在跑、CPU使用率），確保你量到的延遲惡化是「並發推論互相搶資源」造成的，不是被其他無關程序污染的雜訊。如果機器跟當初產出74.54µs那組數字的機器不是同一台/同一規格，要明確回報差異，不能默默換機器讓兩組數字失去可比性。

## 你絕對不要做的事（踩坑提醒）

- **不要**碰任何PnL/成交回測資料或邏輯——這次只做延遲量測，經濟意義的詮釋由我們之後處理，你只要把數字和統計量做對、做乾淨。
- **不要**修改或重新合成PHC-lite的HLS IP/RTL——FPGA那邊的83.16µs是既有結果，這次只在CPU端做事。
- **不要**自己假設deadline門檻、並發數上限、或要不要做N=16——這些已經在上面寫清楚或標明「先回報再決定」，不要自己加碼或省略。
- **不要**把兩輪10,000次的結果混在一起算成一個20,000次的平均——分開回報是為了讓我檢查可重現性，混在一起會讓這個檢查失效。
- **不要**用跟原始benchmark不同的硬體/設定卻不講清楚——這會讓N=1對照組的sanity check失真，整組實驗的可信度都會受質疑。

完成後請回報：(1) 原benchmark程式的位置與執行方式確認、(2) N=1對照組數字是否與74.54/51.0/636.7/43.8µs一致（這是第一個會被檢查的東西，若不一致要說明原因）、(3) 各並發檔位兩輪的完整統計量、(4) deadline miss rate隨並發數的變化、(5) 是否建議加測N=16及理由。我會用教授/reviewer角度檢查你的並發實作是否真的造成資源競爭（而不是被某種鎖或同步機制意外序列化掉，導致並發其實沒發生）、統計量計算是否正確、以及deadline miss rate的詮釋是否被你過度延伸到PnL層面。
