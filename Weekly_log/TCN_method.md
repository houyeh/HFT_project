# TCN 核心方法論與模型架構

在 HFT 高頻造市策略中，我們捨棄了傳統的預測模型 (如 KNN、LSTM)，轉而用 **時間卷積網路 (Temporal Convolutional Network, TCN)**。這份文件是本專案 TCN 模型的總體設計藍圖，詳細記錄了我們為何這樣設計、如何訓練，以及如何挑選超參數以迎合 FPGA 的終極硬體限制。

---

## 0. 核心原理：為什麼要這樣做？
1. 平常是怎麼賺錢的？(無腦賺價差 Dumb Quoting)
概念：想像我們是開在機場的「換匯所」。我們不預測美金明天會漲還是跌，我們只是單純在看板上掛出：「買進美金 30.0 元，賣出美金 30.1 元」。
日常獲利：只要市場是平靜的 (Stationary)，散戶們有買有賣。我們用 30 塊收了散戶的錢，立刻用 30.1 塊賣給另一個散戶。只要這一買一賣完成（不需要行情上漲），我們就白白賺了 0.1 元的價差 (Spread)。
高頻造市商的日常：我們的機器人就是每天掛出成千上萬筆這種雙邊限價單 (Limit Orders)。只要市場沒有明確方向，我們就是穩賺不賠的收費站。
2. 什麼是「毒性大單」？怎麼判斷出來的？(Toxicity Radar)
致命危機：造市商最怕的就是「帶有殺氣的大戶 (Informed Traders)」。假設一個大戶知道利多消息，他毫不考慮成本，直接丟出「市價大買單」，瞬間把 30.1, 30.2, 30.3 的賣單全部買光。
逆向選擇損失 (Adverse Selection)：如果我們傻傻地站在 30.1 賣給他，下一秒價格噴到 31.0，我們就等於被大戶「吃豆腐」，在低點賤賣了資產，這瞬間的虧損會把我們平常賺的價差全部吐回去甚至倒賠。
怎麼用 TCN 判斷：大單要砸下來之前，往往會有微觀的「前兆」。我們的 TCN 吃進了過去數十秒 (100 ticks) 的資料，它觀察的不是價格，而是 「委託簿失衡 (Order Book Imbalance)」 與 「掛單增減的速度」。 當 TCN 發現「買單在異常堆積，而上方的賣單開始偷偷撤走」時，這種盤面壓力失衡就是「毒性」。一旦 TCN 輸出的極端分數突破安全閾值，警戒就會響起。
3. 為什麼「檢測出來並閃躲」就可以賺錢？(Smart Canceling)
高頻交易的終極獲利方程式： 淨利潤 = (平常收取的微小點差總和) - (被大單打穿的巨大滑價損失)
硬體救贖：即使普通 Python 軟體用 TCN 抓到了毒性，但因為網路封包會延遲 (delay=4)，撤單指令還沒送到交易所，單子就被大戶吃掉了，所以會虧錢。
這就是 FPGA 的價值：如果我們把 TCN 燒進 FPGA (延遲趨近於 0)。當 TCN 警報一響，系統擁有絕對的速度優勢，在毒性大單抵達的 0 毫秒前，完成極速撤單 (Freeze / Smart Canceling)，把我們原本掛在 30.1 的賣單抽走。
結論：我們因為「躲開了」這筆會賠大錢的交易，所以我們平常安安穩穩收來的「過路費 (價差)」就能完好無缺地放進口袋。這就是整套系統的核心論述：利用硬體極速躲避災難，確保微小利潤不被吞噬。

## 1. 為什麼選擇 TCN？(Why TCN in HFT?)

### A. 解決時間序列的痛點
高頻交易特徵 (如委託簿失衡 OBI、Spread) 具有高度的時間依賴性。傳統機器學習 (如 Random Forest、XGBoost) 將時間切片視為獨立特徵，無法理解「動能累積」的過程；RNN/LSTM 雖然能理解時間，但其「遞迴依賴 (Recursive Dependency)」導致運算必須一步一步來 (Step-by-step)，無法榨乾 GPU/FPGA 的平行運算效能。

### B. FPGA 硬體極致友善
TCN 的本質是**「純粹的卷積與矩陣乘加 (MACs)」**。
*   沒有 LSTM 複雜的門控機制 (Forget gate, Input gate)，這意味著不需要頻繁存取 SRAM 來保留隱藏狀態 (Hidden states)。
*   卷積窗格可以 100% 在硬體上展開 (Unrolled) 與管線化 (Pipelined)，達成**每個 Clock Cycle 都能吐出一個預測值**的暴力極速。

## 2. 模型核心架構 (Core Architecture)

我們的 TCN 模型 (`src/models/tcn.py`) 建立在三個核心基石上：

### 2.1 因果卷積 (Causal Convolution)
在高頻交易回測中，最致命的錯誤叫做 **未來洩漏 (Look-ahead bias)**。
一般的 1D 卷積在處理時間點 $t$ 時，會「偷看」$t+1$ 的資料 (因為 Padding 補在兩側)。
**因果卷積** 強制將 Padding 全部補在時間序列的「最左側 (過去)」，確保卷積核在計算時刻 $t$ 時，視野只會涵蓋 $t, t-1, t-2...$，物理上斷絕了偷看未來的可能。

### 2.2 膨脹卷積 (Dilated Convolution) 與感受野 (Receptive Field)
為了讓神經網路「看得很遠」，如果只用普通的卷積格，需要疊加幾十層網路，這會搞爆 FPGA 的記憶體。
我們導入了 **膨脹率 (Dilation)**。每一層的跳躍間隔以指數成長：
*   Layer 1: $Dilation = 1$ (看緊鄰的點，擷取微觀雜訊)
*   Layer 2: $Dilation = 2$ (跳一格看，擷取短期趨勢)
*   Layer 3: $Dilation = 4$ (跳三格看，擷取中長期動能)
這樣我們僅用了 3 層、每層 Kernel size = 3 的薄弱網路，就達成了 **29 Ticks** 的絕對感受野：
$$RF = 1 + 2 \times (Kernel - 1) \times (1 + 2 + 4) = 29$$

### 2.3 全域平均池化 (Global Average Pooling, GAP)
網路處理完 100 個時間步 (Sequence Length) 後，以往的做法是「只取最後一個時間點的數值」來過全連接層。
但在高頻資料中，最後一個 Tick 可能剛好是假突破或雜訊。我們改用 GAP，將整個 100 步輸出的特徵圖「沿著時間軸取平均」。這不僅大幅增強了抗噪能力，還把維度從 3D 壓平，節省了最後一層分類器的參數負擔。

## 3. 超參數選擇與權衡 (Hyperparameter Tuning & Trade-offs)

### Channels = [16, 16, 16] (運算效率優先)
我們並非沒有試過 [32, 64, 128] 這種肥大的通道數，但精準度僅提升不到 2%，MACs 運算量卻暴增 10 倍。
選擇 16 的理由：**16 是 2 的 4 次方 ($2^4$)**。在數位電路 (RTL) 與 FPGA DSP 設計中，2的冪次可以最大程度利用 Bit-shift 進行硬體最佳化，並讓記憶體頻寬對齊。

### Sequence Length = 100 (歷史回顧長度)
$S=100$ 確保模型能在 LOB 看到足夠長度（約數十秒）的「委託簿堆疊與撤銷」循環。時間太短無法判斷毒性，太長則會加重 Latency。這 100 個 ticks 會被打包成 3D 張量 `(Batch, 100, Features)` 送入網路。

### Dropout = 0.1 (防過擬合)
我們在每一個卷積層後加入 10% 的 Dropout。金融 Order Book 是全球雜訊最大的數據結構之一，Dropout 迫使模型不能死背特定檔位的數字，而是學習「相對的流動性失衡輪廓」。

## 4. 訓練流程與量化極限瘦身 (Training & INT8 PTQ)

### 第一階段：FP32 全精度訓練
我們使用 PyTorch、CrossEntropyLoss 與 AdamW 優化器。將輸入的 `(B, 100, 5)` 特徵映射為 `(B, 3)` (預測 Up, Down, Stationary 的機率)。這個階段的模型大約有 20 KB。

### 第二階段：INT8 訓練後量化 (Post-Training Quantization)
這是邁向 FPGA 的最後一步。「量化」是將浮點數 (小數點) 壓扁成 8-bit 整數的數學魔法。

0.  **原理**：
市場傳來的價格與我們計算出的 OBI、Spread 原本都是 Float32。量化 (Quantization) 的物理運作如下：

* 到底「什麼東西」被轉成了 INT8？
    * 模型的權重 (Weights) 與偏差 (Biases)：整個模型的神經元參數，已經被絕對鎖死成 -128 到 +127 之間的整數。
    * 層與層之間的特徵圖 (Activations)：上一層卷積算出來的結果，在送到下一層之前，也都會被強制截斷成 INT8。
    * 那 Float32 的「輸入資料」該怎麼辦？ 在 FPGA 的入口端，我們會有一個極為輕量的 Input Quantization Node (輸入量化節點)。 假設 OBI 算出來是 0.42 (Float32)，我們在校準時會算出一個 Input_Scale = 0.0078125。 當這筆資料要餵進 TCN 晶片時，會先過一個簡單的整數除法：0.42 / 0.0078125 = 53.76，四捨五入變成純整數 54 (INT8)。
    * 結論 資料在抵達神經網路的「第一道門」時，就會被強制轉換成 INT8。在整個神經網路的黑盒子裡面， 100% 只會發生 8-bit 整數的乘法與加法 (MACs)，完全不碰任何小數點，直到最後輸出三分類的 Logits 時，才會再乘上一個 Output_Scale，重新還原回可以給軟體判讀的 Float32 機率。

1.  **Calibration (校準)**：抽取 1000 筆 Validation Set 進入網路，跑過一次 FP32 推論，紀錄每一層 Weights 與 Activations 的 `Min` 與 `Max`。
2.  **Symmetric Mapping (對稱映射)**：計算出 `Scale_Factor`，將每一層原本浮動在 $[-1.5, +1.5]$ 的權重，嚴格除以 Scale 並四捨五入收斂至 `[-128, +127]` 之間的 8-bit 整數池中。

**最終心血結晶 (`frozen_tcn_best_model.pt`)**：
*   **大小**：從 20KB 縮減至 **4.8 KB** (可以完全放進最近的 CPU L1 Cache 或 FPGA SRAM，記憶體延遲歸零)。
*   **運算**：推論一次僅需 **460K 整數 MACs**。
*   **精度損失**：小於 0.5%，完美達成「無損精度」的極致硬體準備。這也是本專案高頻撤單防禦 (Smart Canceling) 最堅實的依託！

## 5. 關於輸出

這個 TCN (時間卷積網路) 的輸出，在我們的架構設計中是**「對未來微觀價格走勢的 3 分類機率預測」**。具體來說：

1. **輸出的資料**
最終輸出的資料會是一組 3 個介於 0~1 之間，且加總為 1 的機率值 (因為最後經過了 Softmax 函數處理)。 這三個機率分別代表了 LOB (限價委託簿) 在未來一個極短時間區間內 (例如 10 ticks)，中間價 (Mid-price) 可能發生的狀態：

* P_Down (下跌的機率)
* P_Stationary (盤整或維持原價的機率)
* P_Up (上漲的機率)

2. **輸出決定方法？**
這個機率是由以下四個物理運算步驟「擠壓」出來的：

* **捕捉歷史 (Input)**：系統先丟給模型一個 `(100 ticks, 5 個無因次特徵)` 的 2D 矩陣，這代表了過去一段時間內買賣單的失衡狀況 (OBI) 或是價差(Spread)。
* **萃取動能 (TCN Backbone)**：資料經過 3 層的「因果膨脹卷積」。因為是「因果」，它絕對不會偷看未來；因為是「膨脹」，它能用很少的記憶體一口氣掌握幾十步內的買賣壓變軌趨勢。經過這裡後，資料維度會從 5 個特徵擴張成 16 個神經元通道。
* **過濾雜訊 (Global Average Pooling, GAP)**：把這 100 步的過程，沿著時間軸「取平均」。這就像是捨棄雜訊，只留下這段期間內「最純粹的 16 個市場動能特徵」。
* **線性映射 (Fully Connected Layer)**：最後，透過一個簡單的線性分類器矩陣，將這 16 個特徵投影至 3 個類別上，得出最終的 [P_Down, P_Stationary, P_Up]。

3. **在策略裡，這個輸出扮演什麼角色？**

我們不會拿這些機率去「主動預測方向並開倉」，因為手續費會把你吃光。 

在 `hybrid_market_maker.py` 中，我們拿到這 3 個數字後，會這樣算：

`Alpha 毒性分數 = P_Up - P_Down`

*   平時這分數很低，我們的 FPGA 機器人就是 **「無腦狂掛雙邊單 (Dumb Quoting)」**，拼命賺點差。
*   一旦 LOB 出現巨鯨倒貨的前兆，TCN 預測出的` P_Down `會飆高，導致` Alpha 毒性分數` 的絕對值瞬間超過危險門檻。
*   此時，機器人會不計一切代價啟動 **「極速撤單 (Smart Canceling / Toxicity Freeze)」**，把市場上所有的掛單抽走，閃過被大單貫穿的危險！

*   這就是這 3 個輸出數字在這個 HFT 專題中最核心的價值。
