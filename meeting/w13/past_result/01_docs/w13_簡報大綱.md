## 01｜研究定位：從方向預測改成 Toxic-flow Cancel Filter

**投影片內容**

標題：
**From Directional Prediction to Toxic-flow Cancel Filter**

重點：

* 原始問題：用 LOB 預測短期 mid-price movement
* 實際發現：分類 precision 很低，不適合 active trading
* 重新定位：TCN softmax 作為 toxic-flow risk score
* 策略用途：

  * P(Down) 高 → 撤 bid
  * P(Up) 高 → 撤 ask
* 目前狀態：research candidate，不是 production strategy

**圖表建議**

* 一張流程圖：LOB → TCN Risk Score → Cancel Bid/Ask → Maker-only Strategy

**逐字稿**

> 這週我把專題定位重新整理了一次。原本我們想用 TCN 預測短期價格方向，但分類結果顯示 Up/Down 的 precision 很低，所以它不適合拿來做主動方向交易。
>
> 但它仍然有高 recall 的特性，因此我把模型重新定位成 toxic-flow risk score。也就是說，模型不是告訴我們要買或賣，而是告訴 maker quote 是否有被 adverse selection 打到的風險。
>
> 在策略上，P(Down) 高時撤 bid，避免接下跌刀；P(Up) 高時撤 ask，避免賣在價格上漲前。這就是目前專題的核心方向。

## 07｜Regime Gate：NEW 與 NEW3 需要不同 Gate

**投影片內容**

標題：
**Regime Dependency: Different Markets Need Different Gates**

表格：

| Dataset | Best Gate                  | Net PnL | Active Rate | Interpretation          |
| ------- | -------------------------- | ------: | ----------: | ----------------------- |
| NEW     | spread_filter + TCN 0.55   | 101,455 |       82.4% | spread quality matters  |
| NEW3    | combined_filter + TCN 0.55 |  72,520 |       82.6% | trend+vol+spread needed |

重點：

* NEW：spread filter 足夠
* NEW3：需要 trend + volatility + spread
* 這是 regime dependency 的直接證據
* 還不是 unified production gate selector

**逐字稿**

> Regime gate 的結果很關鍵。NEW 上最好的 gate 是 spread filter，也就是只在 spread 足夠時提供流動性，搭配 TCN cancel 後 PnL 可以到 101,455，active rate 約 82%。
>
> 但 NEW3 不一樣。NEW3 最好的不是單純 spread filter，而是 combined filter，也就是 trend、volatility、spread 一起判斷。這組可以讓 NEW3 從大虧轉成正 PnL 72,520，而且 active rate 仍有 82.6%，不是靠完全不交易。
>
> 這顯示不同 market regime 需要不同 quote control policy。這是目前專題中很重要的研究發現。
>
> 但我要強調，這還不是 production-ready selector，因為目前還沒有建立一個統一的 causal gate selector 來自動決定該用哪種 gate。

**From Mid-move Label to Quote-level Toxic Label**

>
> 這表示 fill-conditional label 比 mid-move label 更貼近交易問題。但它仍然只是 LOB proxy，不是交易所真實 fill truth，因為目前沒有 aggressor-side data。

## 10｜Latency：不能再說 3 ticks 後崩盤

**投影片內容**

標題：
**Latency Sensitivity: Risk Increases, But PnL Is Non-monotonic**

表格：

| Cancel Delay | Net PnL |
| -----------: | ------: |
|            0 |  84,980 |
|            1 |  99,550 |
|            2 |  92,280 |
|            3 | 113,330 |
|            5 | 116,080 |
|           10 |  61,650 |

重點：

* delayed toxic loss increases with delay
* net PnL is non-monotonic
* delay=10 明顯變差
* FPGA relevance = reduce worst-case cancel latency
* 不是「3 ticks 後崩盤」

**逐字稿**

> 這頁我要特別修正之前的說法。不能說延遲超過 3 ticks 後策略崩盤。
>
> 實際上 cancel delay 的 net PnL 是非單調的。delay 1、3、5 的 PnL 反而比 delay 0 高，可能是因為部分 false-positive cancel 被延後，讓策略接到更多 good fills。
>
> 但 delayed toxic loss 確實會隨 delay 增加，而且 delay 10 時 PnL 開始明顯下降到 61,650。
>
> 所以 FPGA 的合理性不是「已經證明 3 ticks 後崩盤」，而是作為風控硬體，用來降低 worst-case cancel latency 和 delayed toxic loss。這個論述比較誠實。
